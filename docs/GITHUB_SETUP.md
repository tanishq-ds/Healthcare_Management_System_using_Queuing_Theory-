### 3. Security Configuration

#### Environment Variables (.env)
- **Location**: Root directory (NOT committed to GitHub)
- **Template**: `.env.example` (committed for reference)
- **Purpose**: Store sensitive database credentials
```bash
# .env file structure
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=hospital_management
DB_PORT=3306
```

#### .gitignore Configuration
Protected files/folders:
- `.env` and all `.env.*` files
- Virtual environments (`venv/`, `env/`, `test_env/`)
- CSV data files (available on Kaggle)
- Large model files (`.pkl`, `.joblib`)
- Database files (`.db`, `.sqlite`)
- Python cache (`__pycache__/`)

### 4. Branch Strategy

**Main Branch**

**Development Workflow**
1. Work on features locally
2. Test thoroughly
3. Commit with descriptive messages
4. Push to main (currently solo development)

### 5. Commit Message Convention

Format: `<type>: <description>`

**Types:**
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation updates
- `refactor`: Code refactoring
- `test`: Adding tests
- `chore`: Maintenance tasks

**Examples:**
```
feat: Add XGBoost model for ward classification
fix: Resolve MySQL connection timeout issue
docs: Update README with queue analytics dashboard
refactor: Extract database functions to separate module
```

### 6. GitHub Desktop Usage

**Tools Used:**

**Typical Workflow:**
1. Make changes locally
2. Review changes in GitHub Desktop

4. Commit to main branch
5. Push to origin

### 9. Kaggle Dataset Integration

CSV files excluded from repository. Users must download from:
- Patient Priority: https://www.kaggle.com/datasets/hossamahmedaly/patient-priority-classification
- Hospital Beds: https://www.kaggle.com/datasets/jaderz/hospital-beds-management

Place in `data/raw/` before running notebooks.

### 10. Model Files Strategy

- Excluded from GitHub (too large)

- Demonstrates reproducibility

**Future Options:**
